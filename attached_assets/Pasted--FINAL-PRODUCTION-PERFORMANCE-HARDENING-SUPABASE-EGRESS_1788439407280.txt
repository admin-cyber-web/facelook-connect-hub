# FINAL PRODUCTION PERFORMANCE HARDENING

## SUPABASE EGRESS + MOBILE HEATING + BATTERY DRAIN

The application already has a major performance deep-clean implemented.

Your job now is to perform the **FINAL production hardening pass**.

The two original problems are:

1. One user can generate approximately 1GB+ of Supabase/network usage per day.
2. Mobile devices become hot and battery drains rapidly shortly after opening the app.

The goal is to eliminate unnecessary resource consumption while preserving 100% of the application's existing functionality.

---

# ABSOLUTE PROTECTION RULE

The existing performance fixes are the baseline.

DO NOT undo, replace, or weaken them.

Existing fixes include:

* shared Web Audio context
* audio idle suspension
* Agora cleanup
* background call termination
* camera background shutdown/restart
* story timer pause
* story audio/video pause
* one-video story decoder
* Circle viewport video playback
* object URL cleanup
* Magnet request guards
* recipient-scoped Realtime listener
* bounded comments/admin queries
* bounded Magnet leaderboard
* explicit database projections
* Survey duplicate-read consolidation
* safety-engine limits
* wildcard query cleanup
* visibility-aware media handling

Preserve all of these.

# 1. FIND THE ACTUAL EGRESS SOURCE

Do not assume that "cache egress" is caused by browser cache.

Determine what is actually consuming bandwidth.

Separate:

### A. Database egress

Large/repeated `.select()` responses.

### B. Realtime egress

Excessive Realtime events/messages.

### C. Storage egress

Images/videos repeatedly downloaded.

### D. Video egress

Autoplay, preload, duplicate video downloads.

### E. Image egress

Large images/original files repeatedly downloaded.

### F. Auth traffic

Repeated session/user/profile requests.

### G. Other APIs

Any external API repeatedly called.

The final report must identify the largest contributors.

---

# 2. ZERO UNNECESSARY IDLE TRAFFIC

When the user opens the app and does NOTHING:

There must NOT be:

* aggressive polling
* repeated feed requests
* repeated profile requests
* repeated notification requests
* repeated storage requests
* video downloads
* audio downloads
* unnecessary API calls
* duplicate Realtime subscriptions
* duplicate Realtime events caused by client logic
* continuously running timers

Normal authentication/session maintenance is acceptable.

Required realtime features are acceptable.

But unnecessary background traffic is NOT acceptable.

---

# 3. SUPABASE REALTIME HARDENING

Audit every `.channel()` and `.subscribe()`.

For each subscription:

* exactly identify why it exists
* identify which component owns it
* ensure cleanup on unmount
* prevent duplicate channels
* prevent subscriptions on every render
* prevent subscriptions after navigation from accumulating
* prevent subscriptions after logout
* prevent duplicate listeners

Use filters whenever the application only needs events for a particular user/conversation/entity.

Do NOT globally disable Realtime.

Do NOT replace required Realtime features with polling.

---

# 4. CHAT HARDENING

Chat is especially important.

The current chat functionality must remain realtime.

But:

* do not poll aggressively when Realtime already handles updates
* do not refetch the entire conversation for one new message
* do not refetch the entire feed because of a chat event
* do not repeatedly fetch old messages
* paginate historical messages
* load older messages only when needed
* ensure leaving Chat removes unnecessary listeners
* ensure reopening Chat does not create duplicate listeners

If fallback polling exists, it must:

* only operate when genuinely required
* only operate while Chat is visible/active
* stop when Chat is hidden/inactive
* stop when the user leaves Chat
* use a conservative interval

Do not remove legitimate fallback behavior without evidence.

---

# 5. FEED HARDENING

Home/Fame Feed must NOT continuously download the entire feed.

Implement/verify:

* bounded initial load
* pagination
* incremental loading
* no repeated full-feed fetches
* no full-feed refetch after a single like/comment
* local update of affected post where safe
* visibility-aware media loading

Do not repeatedly fetch the same posts.

---

# 6. IMAGE EGRESS HARDENING

Audit all Supabase Storage image usage.

Find:

* images downloaded repeatedly
* original-resolution images used where unnecessary
* URLs regenerated every render
* components remounting and downloading images again
* offscreen images loading unnecessarily

Use browser-native lazy loading where appropriate.

Do not destroy image quality unnecessarily.

Prefer appropriate thumbnails/resized variants when the application already supports them.

Do not make private content public merely to improve caching.

---

# 7. VIDEO EGRESS HARDENING

This is extremely important.

Videos can consume hundreds of MB very quickly.

For every video:

* do not preload unnecessary videos
* do not autoplay multiple videos
* only the visible/active video should normally play
* pause offscreen videos
* stop video when navigating away
* stop video when app is backgrounded
* avoid loading video source until needed
* avoid duplicate video elements
* avoid repeated signed URL generation
* release temporary resources

Use IntersectionObserver where appropriate.

Use visibility/page lifecycle handling.

Do not preload entire Reel/Circle/Story video collections.

---

# 8. STORY HARDENING

Stories must:

* load only the current/necessary story media
* pause when hidden
* stop audio when hidden
* stop video when hidden
* stop timers when hidden
* avoid downloading all story videos unnecessarily
* avoid multiple video decoders
* avoid repeatedly fetching the same story media

Preserve the existing one-video decoder optimization.

---

# 9. CAMERA / MICROPHONE HARDENING

Camera and microphone must NEVER remain active when their feature is not being used.

When the app is:

* backgrounded
* navigating away
* call ended
* camera screen closed

properly stop/release media tracks.

Do not continuously request camera/microphone access.

Preserve existing Agora cleanup.

---

# 10. AUDIO HARDENING

Preserve the existing shared Web Audio implementation.

Audit remaining `new AudioContext()` / `new webkitAudioContext()` usage.

Only change additional AudioContext instances if they are proven to cause unnecessary resource usage or duplicate audio engines.

Do NOT blindly merge unrelated audio systems.

Do NOT break sound effects, calls, music, or notifications.

---

# 11. OBJECT URL HARDENING

Audit every:

```text
URL.createObjectURL()
```

For every generated object URL determine:

* owner
* lifetime
* cleanup location

Ensure temporary upload previews are revoked after they are no longer needed.

Do NOT revoke URLs while the image/video still needs them.

Do not blindly add `revokeObjectURL()` everywhere.

---

# 12. AUTH HARDENING

Ensure there is no repeated:

```text
getSession()
getUser()
auth listener
profile fetch
```

caused by React renders or navigation.

There should be a stable authentication lifecycle.

Do not modify authentication security.

Never expose:

* service role key
* access token
* refresh token
* password
* private cookies

---

# 13. QUERY HARDENING

Audit every Supabase query.

Avoid:

```text
select("*")
```

where unnecessary.

Select only required columns.

Add reasonable limits.

Use pagination for large datasets.

Do NOT blindly add indexes or change database schema.

Only optimize queries supported by actual usage/code evidence.

---

# 14. DUPLICATE REQUEST DETECTION

Find cases where one user action causes multiple identical requests.

Example:

```text
ONE page load
→ profile request × 4
→ notifications request × 3
→ feed request × 3
```

Fix the duplication.

Also check:

```text
ONE like
→ like request
→ full feed request
→ profile request
→ notification request
→ duplicate feed request
```

Only perform necessary work.

---

# 15. VISIBILITY / BACKGROUND HARDENING

When:

```text
document.hidden === true
```

or the app is backgrounded:

Pause/stop where appropriate:

* videos
* camera
* microphone
* story timers
* animations
* polling
* nonessential refreshes
* expensive CPU work

Do not unnecessarily disconnect required authentication functionality.

Do not break Realtime features that genuinely need to remain active.

---

# 16. MEMORY / CPU LEAK AUDIT

Check for:

* event listeners without cleanup
* timers without cleanup
* observers without disconnect
* Realtime channels without removal
* media tracks without stop()
* audio contexts left running
* object URLs without appropriate cleanup
* repeated state updates
* infinite render/effect loops

Fix only confirmed issues.

---

# 17. DO NOT USE "CACHE" AS A BAND-AID

IMPORTANT:

Do NOT solve the 1GB/day problem merely by:

* adding arbitrary browser caching
* increasing cache duration
* hiding requests
* disabling features
* reducing functionality
* disabling Realtime
* switching to fake data

Caching can help, but the primary objective is to prevent unnecessary data from being requested/downloaded in the first place.

---

# 18. SUPABASE STORAGE CACHE

Where safe and appropriate, allow browser/CDN caching of immutable public media.

For user/private media, preserve security.

Do not make private files public just for caching.

Do not change storage security policies without explicit evidence and approval.

---

# 19. REALTIME EVENT EFFICIENCY

A Realtime event should update only the necessary UI.

Do NOT respond to one event by refetching multiple unrelated tables.

For example:

```text
New chat message
BAD:
refetch Home
refetch Profile
refetch Notifications
refetch entire Chat
GOOD:
update the relevant conversation/message state
```

Apply the same principle to:

* likes
* comments
* notifications
* Circle activity
* messages
