# PHASE 3 — FIX SUPABASE REALTIME

Realtime is a major suspect.

For every realtime channel:

### Correct pattern

```ts
useEffect(() => {
  const channel = supabase
    .channel(`unique-channel-name`)
    .on(
      'postgres_changes',
      {
        event: 'INSERT',
        schema: 'public',
        table: 'notifications'
      },
      handleEvent
    )
    .subscribe();

  return () => {
    supabase.removeChannel(channel);
  };
}, []);
```

Ensure cleanup happens whenever the component unmounts.

### Prevent:

* multiple subscriptions to the same channel
* subscription creation on every render
* subscriptions created because of changing function references
* subscriptions surviving route changes
* duplicate listeners after login/logout
* listeners created inside loops
* listeners created inside frequently changing effects

# PHASE 4 — DO NOT SUBSCRIBE TO ENTIRE TABLES UNNECESSARILY

Audit all realtime subscriptions.

If a component only needs data belonging to the current user, don't listen to the entire table.

For example, avoid unnecessarily broad subscriptions such as:

```text
all notifications
all messages
all posts
all likes
all comments
```

Where appropriate, use filters so the client receives only relevant changes.

Example:

```ts
.on(
  'postgres_changes',
  {
    event: 'INSERT',
    schema: 'public',
    table: 'notifications',
    filter: `user_id=eq.${user.id}`
  },
  handler
)
```

Use the same principle for messages, notifications, etc.

Do not add filters blindly if the current Supabase schema does not support the required column.

# PHASE 5 — STOP POLLING WHERE REALTIME IS ALREADY USED

If realtime already provides updates, don't also repeatedly fetch the same data.

Bad:

```text
Every 2 seconds:
fetch notifications

AND

Supabase realtime:
listen for notifications
```

Use realtime for live changes and normal fetches only when needed.

If polling is genuinely required, increase the interval substantially and stop polling when:

* tab is hidden
* app is backgrounded
* component is unmounted
* user is logged out
* relevant page is not active

Use Page Visibility API where appropriate.

# PHASE 6 — FIX setInterval / setTimeout LEAKS

Every timer must be cleaned up.

Bad:

```ts
useEffect(() => {
  setInterval(loadData, 5000);
}, []);
```

Correct:

```ts
useEffect(() => {
  const interval = setInterval(loadData, 5000);

  return () => clearInterval(interval);
}, []);
```

Also inspect recursive `setTimeout` implementations for leaks.

Do not allow multiple timers to accumulate after navigation or component remounts.
