# 🚀 FLICKS INDIA — Advanced Local + Interest Recommendation & People Discovery System

Existing Flicks India app mein ek **advanced, smooth, privacy-first recommendation system** implement karo. Existing UI, authentication, database structure, features aur design ko break mat karo. Existing functionality safe rehni chahiye.

Goal ye hai ki Flicks India user ko uske **local area, district, state, interests, mutual connections aur relevant activity** ke basis par highly personalized content aur people suggestions de — lekin recommendations natural aur smooth feel hon, spammy nahi.

---

## 1. 📍 USER LOCATION PROFILE

Profile/Edit Profile mein existing profile system ke andar ye information support karo:

* State
* District
* City/Town
* Pincode
* Optional locality/area

Location hierarchy:

```text
Pincode / Locality
        ↓
City / Town
        ↓
District
        ↓
State
        ↓
India
```

Location ko recommendation system mein structured form mein store/use karo.

Important:

* User ki exact GPS location ko unnecessarily expose mat karo.
* Public profile par exact address kabhi display mat karo.
* Recommendation ke liye broad location matching use karo.

# 5. 🔐 PUBLIC / PRIVATE PROFILE RULE — VERY IMPORTANT

App mein existing **Private Profile mode** already hai.

Is existing privacy system ko respect karna mandatory hai.

### PUBLIC PROFILE

Agar user ka profile:

```text
profile_visibility = public
```

hai, tab eligible local users ko recommendation mein dikhaya ja sakta hai.

Use signals:

* Same locality
* Same pincode
* Same district
* Same state
* Similar interests
* Mutual connections
* Relevant activity

---

### PRIVATE PROFILE

Agar user:

```text
profile_visibility = private
```

kar deta hai,

to us user ko **location-based People Recommendation mein automatically recommend MAT karo.**

Uska:

* profile suggestion
* local people suggestion
* “new person from your area”
* recommendation card

automatically hide/remove ho.

Private user ki privacy priority highest honi chahiye.

### IMPORTANT:

Privacy status change hone ke baad cached recommendation cards bhi immediately invalidate/remove hone chahiye.

Example:

```text
User A = Public
↓
Recommended to nearby users
↓
User A changes to Private
↓
Existing recommendation cache invalidated
↓
User A no longer appears in local suggestions
```

No stale private-profile recommendations.

# 12. 🔒 PRIVACY RULES

Recommendation engine ko kabhi bhi private profile ko bypass nahi karna hai.

Rules:

```text
IF profile = PRIVATE
→ Do not show in public/local people recommendations

IF profile = PUBLIC
→ Eligible for recommendation based on allowed signals

IF user disables "People From My Area"
→ Do not show local people recommendations to that user

IF user disables "Local Content First"
→ Use normal personalized feed ranking
```

Existing block, mute, report, restricted-user aur privacy systems ko recommendation engine mein respect karo.

Blocked users ko ek dusre ko recommend mat karo.

---

# 13. ⚡ PERFORMANCE REQUIREMENTS

Ye feature existing app ko slow ya heat nahi karna chahiye.

DO NOT:

* continuous polling
* unnecessary setInterval
* repeated full-table queries
* client-side processing of thousands of users
* repeated realtime listeners
* unnecessary location requests

Use:

* indexed database queries
* pagination
* caching
* batched recommendation generation
* debounced updates
* lazy loading
* server-side ranking where practical
* efficient Supabase queries
* proper realtime subscriptions only where required

Recommendation cards ko virtualize/lazy-load karo agar list long ho.

❌ Exact distance like “47 meters away”

✅ “From your district”
✅ “From your area”
